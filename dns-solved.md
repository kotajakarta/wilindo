# Troubleshooting: DNS Gagal Saat `podman pull` (RHEL + Tailscale)

## Gejala

`./dep.sh` gagal di langkah build dengan error:

```
Error: unable to copy from source docker://node:24-alpine: initializing source docker://node:24-alpine:
pinging container registry registry-1.docker.io: Get "https://registry-1.docker.io/v2/":
dial tcp: lookup registry-1.docker.io on [fd7a:115c:a1e0::53]:53: server misbehaving
```

Podman menarik image lewat DNS **host** (bukan DNS di dalam container), jadi kalau resolver DNS host bermasalah, semua `podman pull` ikut gagal — bukan masalah kode/project.

## Diagnosis

1. `tailscale debug prefs | grep -i dns` → `"CorpDNS": false` — Tailscale MagicDNS **tidak** sedang override DNS sistem. Bukan penyebabnya.
2. `tailscale status` menampilkan health warning:
   ```
   # System DNS config not ideal. /etc/resolv.conf overwritten. See https://tailscale.com/s/dns-fight
   ```
3. `nslookup`/`dig` gagal dengan `connection refused` ke `::1#53` dan `127.0.0.1#53` — resolver lokal di loopback tidak ada yang listen.
4. `cat /etc/resolv.conf` → isinya cuma:
   ```
   # Generated by NetworkManager
   ```
   **Tidak ada baris `nameserver` sama sekali.** (glibc fallback default ke `127.0.0.1` kalau resolv.conf kosong — itu sumber error `::1#53`/`127.0.0.1#53` refused di atas.)
5. `systemctl status systemd-resolved` → `Unit systemd-resolved.service could not be found` — sistem ini **tidak pakai** systemd-resolved sama sekali, jadi bukan konflik systemd-resolved vs NetworkManager yang biasa terjadi.
6. Kesimpulan: NetworkManager sendiri gagal mengisi nameserver ke `/etc/resolv.conf` (kemungkinan sisa konflik dari Tailscale DNS yang pernah aktif sebelumnya), padahal `nmcli general status` melaporkan `connected, full` (connectivity check NetworkManager tidak bergantung pada DNS yang benar-benar berfungsi).

## Root Cause

`/etc/resolv.conf` kosong (tidak ada `nameserver`) karena NetworkManager gagal mengisinya — bukan karena Tailscale, bukan karena systemd-resolved (tidak terpasang).

## Fix

### 1. Fix cepat (unblock langsung)

```bash
sudo bash -c 'cat > /etc/resolv.conf <<EOF
nameserver 1.1.1.1
nameserver 8.8.8.8
EOF'

getent hosts registry-1.docker.io   # harus balikin IP, bukan kosong
```

### 2. Fix permanen (biar tidak kosong lagi setelah reboot/reconnect)

Cari interface yang pegang default route dulu:

```bash
ip route show default
# contoh output: default via 192.168.1.1 dev ens18 ...
```

Set DNS langsung di connection profile NetworkManager interface tsb (ganti `ens18` sesuai hasil di atas — **jangan** pakai interface `tailscale0`, itu dikelola sendiri oleh `tailscaled`):

```bash
sudo nmcli connection modify ens18 ipv4.dns "1.1.1.1 8.8.8.8"
sudo nmcli connection modify ens18 ipv4.ignore-auto-dns yes
sudo nmcli connection up ens18

cat /etc/resolv.conf          # harus ada nameserver 1.1.1.1 / 8.8.8.8
getent hosts registry-1.docker.io
```

`ipv4.ignore-auto-dns yes` mencegah NetworkManager menimpa lagi dengan DNS dari DHCP (yang kosong/rusak), jadi setting ini bertahan setelah reboot/reconnect.

## Verifikasi Akhir

```bash
cd /webku/appsku/wilindo
./dep.sh
```

Build berhasil menarik `node:24-alpine` dan deployment lanjut normal.

## Kalau Terjadi Lagi (server/node lain)

1. `getent hosts registry-1.docker.io` — kalau kosong/gagal, ini DNS host, bukan masalah project.
2. `tailscale debug prefs | grep -i dns` — pastikan `CorpDNS: false` (kalau `true`, Tailscale MagicDNS yang override; jalankan `tailscale set --accept-dns=false`).
3. `cat /etc/resolv.conf` — kalau kosong/tanpa baris `nameserver`, langsung ke bagian **Fix** di atas (skip diagnosis systemd-resolved kalau sebelumnya sudah dipastikan tidak terpasang).
